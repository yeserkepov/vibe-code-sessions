# Vibe Coding Session — Гайд для фасилитатора

> Аудитория: полные новички (нет опыта кода)  
> Длительность: 4 часа  
> Инструмент: Claude Code (терминал, без IDE)  
> Размер группы: оптимум 5–12 человек

---

## Цель сессии

Участник уходит с **работающим личным проектом** и пониманием одного навыка: как описывать задачу AI чтобы получить результат. Не "научиться программировать" — это слишком абстрактно. Конкретный артефакт в руках.

#### ⭐ Личная страница-визитка

**Что получится:** HTML файл, открывается в любом браузере. Можно отправить ссылку если выложить на GitHub Pages.

**Шаги:**

1. **Создать базовую структуру**
```
Создай одностраничный HTML файл — личная визитка.
Моё имя: [ИМЯ]
Должность / чем занимаюсь: [ТЕКСТ]
Email: [EMAIL]
Стиль: тёмный фон (#1a1a2e), белый текст, минималистично, по центру.
Без внешних библиотек — только HTML и CSS в одном файле.
```

2. **Добавить фото или аватар**
```
Добавь круглый аватар в верх страницы. Пока используй placeholder картинку
с сервиса via.placeholder.com размером 150x150
```

3. **Добавить ссылки на соцсети**
```
Добавь кнопки-иконки для Telegram, Instagram и LinkedIn.
Используй emoji как иконки (✈️ 📸 💼). Ссылки пока пустые (#).
Кнопки в ряд, с отступами.
```

4. **Добавить анимацию**
```
Добавь плавное появление всего контента при загрузке страницы (fade in анимация через CSS).
И добавь hover эффект на кнопки — лёгкое увеличение при наведении.
```

5. **Финальная полировка**
```
Сделай страницу адаптивной для мобильного телефона.
Проверь что на маленьком экране всё читается и не вылезает за края.
```

**Как запустить:** Найти файл в папке → двойной клик → откроется в браузере.  
**Деплой:** GitHub Pages или Netlify Drop (перетащить файл на netlify.com/drop).

#### ⭐⭐ Скрипт для переименования файлов

**Что получится:** Python скрипт который берёт папку с файлами и переименовывает их по правилу.

**Шаги:**

1. **Создать базовый скрипт**
```
Создай Python скрипт rename_files.py который:
- Спрашивает путь к папке
- Выводит список всех файлов в ней
- Больше пока ничего не делает
```

2. **Добавить логику переименования**
```
Добавь в скрипт возможность добавлять номер в начало каждого файла.
Например: "фото.jpg" → "001_фото.jpg", "документ.pdf" → "002_документ.pdf"
Сортировать по алфавиту перед нумерацией.
```

3. **Добавить предпросмотр**
```
Перед переименованием покажи список: что было → что станет.
Спроси подтверждение у пользователя (y/n) прежде чем применять изменения.
```

4. **Добавить фильтр по типу файла**
```
Добавь параметр: пользователь вводит расширение (например .jpg или .pdf)
и скрипт переименовывает только файлы с этим расширением.
```

5. **Добавить лог**
```
После переименования сохрани лог в файл rename_log.txt:
дата, папка, список изменений (старое имя → новое имя).
```

**Как запустить:** `python rename_files.py`  
**Тест:** создать тестовую папку с 5-6 файлами, запустить на ней.

#### ⭐⭐ Телеграм-бот (эхо или факты)

**Что получится:** Бот в Telegram который отвечает на сообщения.

**Подготовка (сделать до кода):**
1. Написать @BotFather в Telegram → `/newbot` → получить токен
2. Сохранить токен — он нужен в шаге 1

**Шаги:**

1. **Создать эхо-бот**
```
Создай Python телеграм-бот используя библиотеку python-telegram-bot версии 20+.
Токен бота: [ТОКЕН]
Функционал: бот получает любое текстовое сообщение и отвечает тем же текстом обратно.
Добавь команду /start с приветственным сообщением.
```

2. **Установить зависимости и запустить**
```
Напиши команду для установки нужных библиотек и как запустить этого бота.
```

3. **Добавить случайные факты**
```
Добавь команду /fact — бот отвечает случайным интересным фактом.
Сделай список из 15 фактов прямо в коде (не нужен внешний API).
```

4. **Добавить команду /help**
```
Добавь команду /help которая показывает список всех доступных команд с описанием.
```

5. **Добавить персонализацию**
```
Добавь команду /setname — пользователь вводит своё имя, бот запоминает его
и обращается по имени в следующих сообщениях.
Имя хранить в словаре в памяти (не нужна база данных).
```

**Как запустить:** `python bot.py` — держать терминал открытым пока бот работает.  
**Деплой:** для сессии достаточно локального запуска, показать с телефона.

#### ⭐ Генератор случайных рецептов

**Что получится:** Python скрипт — вводишь ингредиенты, получаешь рецепт.

**Шаги:**

1. **Создать базовый генератор**
```
Создай Python скрипт recipe_generator.py.
Скрипт спрашивает: "Какие ингредиенты у тебя есть? (через запятую)"
Пользователь вводит список.
Скрипт выбирает случайный рецепт из встроенного списка где есть хотя бы 2 введённых ингредиента.
Добавь 10 рецептов с ингредиентами прямо в код.
```

2. **Улучшить вывод рецепта**
```
Рецепт выводить красиво:
- Название большими буквами
- Список ингредиентов с галочками ✓
- Шаги приготовления пронумерованно
- Время приготовления
```

3. **Добавить фильтр по диете**
```
Добавь вопрос: "Есть ли ограничения?" с вариантами:
1 — без ограничений
2 — вегетарианское
3 — без глютена
Фильтровать рецепты по выбору. Пометь каждый рецепт тегами в коде.
```

4. **Добавить сохранение в избранное**
```
После показа рецепта спроси "Добавить в избранное? (y/n)"
Если да — сохрани рецепт в файл favorites.txt.
Добавь команду при запуске: если ввести "избранное" — показать сохранённые рецепты.
```

5. **Добавить красивое меню**
```
Сделай главное меню при запуске:
1. Найти рецепт по ингредиентам
2. Случайный рецепт
3. Мои избранные
4. Выход
Цикл — меню показывается снова после каждого действия.
```

**Как запустить:** `python recipe_generator.py`

#### ⭐⭐ Скрипт для скачивания картинок

**Что получится:** Python скрипт скачивает картинки по списку URL или с веб-страницы.

**Шаги:**

1. **Создать базовый скрипт**
```
Создай Python скрипт downloader.py.
Скрипт читает файл urls.txt (каждая строка — один URL картинки).
Скачивает каждую картинку в папку downloads/.
Показывает прогресс: "Скачиваю 1 из 10: [url]"
Использует библиотеку requests.
```

2. **Добавить умные имена файлов**
```
При сохранении файла:
- Брать имя из URL (последняя часть пути)
- Если имя уже существует — добавить номер: photo.jpg → photo_1.jpg
- Если имя не читаемое — сохранять как image_001.jpg, image_002.jpg и т.д.
```

3. **Добавить фильтр по типу**
```
Добавь параметр запуска: пользователь вводит типы файлов через запятую (jpg,png,gif).
Скачивать только файлы указанных типов, остальные пропускать.
```

4. **Добавить отчёт**
```
После скачивания показать итог:
- Успешно скачано: N файлов
- Пропущено/ошибок: N файлов
- Список ошибок с URL и причиной
- Сохранить отчёт в download_log.txt
```

5. **Добавить ограничение скорости**
```
Добавь паузу 1 секунда между скачиваниями чтобы не перегружать сервер.
Добавь параметр: пользователь может указать задержку в секундах (по умолчанию 1).
Показывать оставшееся время: "Осталось примерно X секунд"
```

**Как запустить:** `python downloader.py`  
**Тест:** создать urls.txt с 3-5 публичными URL картинок.

## Расписание сессии

### Блок 1: Ориентация (0:00 – 0:30)

**0:00–0:10 — Что такое вайбкодинг (10 мин)**

Объяснить концепцию в 3 предложениях:
> "Вайбкодинг — это когда ты описываешь что хочешь словами, а AI пишет код. Твоя задача — не знать синтаксис, а уметь объяснить задачу. Мы сегодня именно этому и учимся."

Показать: открыть терминал, написать `claude` — всё. Это весь инструмент.

**0:10–0:20 — Демо фасилитатора (10 мин)**

Построить что-то маленькое прямо сейчас на глазах у всех. Например:
```
Создай Python скрипт который спрашивает моё имя и выводит приветствие с текущим временем
```
Запустить. Показать результат. Попросить добавить фичу:
```
Добавь чтобы имя сохранялось в файл greeting_log.txt с датой
```
Главный посыл: **это разговор, не программирование**.

**0:20–0:30 — Setup у участников (10 мин)**

Все открывают терминал и пишут первый промпт:
```
Привет! Я новичок. Создай Python скрипт который выводит мои инициалы большими буквами из звёздочек
```
Цель — убедиться что Claude Code работает у всех. Кто застрял — fallback на claude.ai.

### Блок 2: Обучение промптингу (0:30 – 1:00)

**Главный навык сессии.** Потратить 30 минут только на это.

#### Принципы хорошего промпта

**1. Контекст + действие + ограничения**

Плохо:
```
сделай сайт
```

Хорошо:
```
Создай одностраничный HTML файл — личная визитка.
Контент: моё имя "Алия", должность "дизайнер", email "aliya@email.com".
Стиль: тёмный фон, белый текст, минималистично.
Без внешних библиотек, только чистый HTML и CSS в одном файле.
```

**2. Итерация — нормально**

Учить не бояться "сломать". Типичный диалог:
```
[первый промпт] → результат
[второй] → "добавь кнопку"
[третий] → "измени цвет на синий"
[четвёртый] → "это не работает, вот ошибка: [вставить ошибку]"
```
Каждый шаг — один запрос. Не пихать всё сразу.

**3. Вставлять ошибки как есть**

Участники боятся ошибок. Показать: скопировать ошибку из терминала → вставить в Claude → он починит.
```
Запускаю скрипт и получаю ошибку:
ModuleNotFoundError: No module named 'requests'
Как исправить?
```

**4. Попросить объяснение**

```
Объясни что делает эта строка кода простыми словами:
[вставить строку]
```

#### Упражнение (15 мин)

Все берут один и тот же базовый скрипт и по очереди добавляют фичи через промпты. Кто добавил больше интересных фич за 10 минут — победил. Разбираем разные формулировки промптов.

### Блок 3: Личный проект (1:00 – 3:30)

**Это ядро сессии. 2.5 часа свободной работы.**

#### Роль фасилитатора в этот период

Не чинить за участников. Задавать вопросы:
- "Что ты хочешь чтобы произошло?"
- "Как ты это объяснишь Claude?"

Вмешиваться только если человек застрял более 5 минут и не может сформулировать задачу.

#### Чекпоинты

| Время | Что должно быть у участника |
|-------|----------------------------|
| 1:30 | Базовая структура проекта работает |
| 2:30 | Основная функциональность готова |

#### Когда участник "застрял"

Типичные ситуации и что говорить:

**"Я не знаю что написать"**  
→ "Опиши мне словами что должен делать твой проект. Теперь напиши это же Claude."

**"Ничего не работает"**  
→ "Скопируй ошибку и вставь её в Claude с вопросом 'как это исправить'"

**"Claude сделал не то"**  
→ "Напиши ему что конкретно не так. Например: 'ты сделал X, а мне нужно Y'"

**"Я хочу добавить слишком много"**  
→ Помочь урезать scope. "Выбери одну главную фичу. Остальное — следующая сессия."

**"Мой проект скучный"**  
→ Нормально. Задача — чтобы работало. Крутость не цель первой сессии.

#### Частые технические проблемы

| Проблема | Решение |
|----------|---------|
| `command not found: claude` | `npm install -g @anthropic-ai/claude-code` |
| `ModuleNotFoundError` | Попросить Claude написать команду установки |
| `Permission denied` | На Windows: запустить терминал от администратора |
| Claude Code завис | Ctrl+C, перезапустить `claude` |
| Файл создан но не открывается | Попросить Claude написать как запустить |
| Телеграм бот не отвечает | Проверить токен, запросить у @BotFather заново |

### Блок 4: Деплой и демо (3:20 – 4:00)

**Деплой (3:20 – 3:40)**

Зависит от типа проекта:

| Тип | Куда деплоить |
|-----|---------------|
| HTML страница | GitHub Pages (бесплатно, 2 мин) или просто открыть файл в браузере |
| Python скрипт | Оставить локально, показать запуск |
| Телеграм-бот | Оставить запущенным, показать в телефоне |

Для HTML — самый быстрый путь:
```
Создай для моей страницы инструкцию как выложить её на GitHub Pages за 5 шагов
```

**Демо (3:40 – 4:00)**

Каждый участник показывает свой проект — **2 минуты максимум**.  
Формат: "Что это, что умеет, что было сложнее всего."

Не оценивать качество кода. Оценивать: работает или нет.

## Частые вопросы участников

**"Это вообще программирование?"**  
Да. Промпт — это спецификация. Умение точно описать задачу — самый ценный навык разработчика.

**"Мне надо учить Python/JS?"**  
Не обязательно сейчас. Но со временем понимание кода помогает писать лучшие промпты.

**"Что если AI ошибается?"**  
Норма. Итерируй. Реальные разработчики делают так же.

**"Как сохранить то что я сделал?"**  
Claude Code создаёт файлы в текущей папке. Показать где папка, как найти файлы.

**"Можно ли зарабатывать этим?"**  
Да. Много людей строят MVP, автоматизируют рутину, делают инструменты для своей работы.
